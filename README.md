# GlassTube

**GlassTube** — спокойный видеохостинг в стиле *Liquid Glass*. Без агрессивного
удержания внимания, бесконечной ленты и тёмных паттернов. Чистый стеклянный
интерфейс, тёмная и светлая темы, аккуратные анимации и высокая читаемость.

Проект — полноценный MVP на **PHP 8.2+ (без Composer/фреймворков)**, **MySQL 8+**,
чистом **CSS** и **Vanilla JS (ES-модули)**.

---

## Возможности

- Регистрация / вход / выход, роли `user` и `admin`, автосоздание канала.
- Загрузка видео (mp4/webm) с проверкой размера, MIME и расширения, случайными
  именами файлов и хранением **вне публичной директории**.
- Безопасный стриминг с поддержкой **HTTP Range** (206 / 416).
- Страница просмотра: плеер, лайки, сохранение («Смотреть позже»), подписки,
  история, похожие видео, комментарии, ИИ-помощник.
- Категории, теги, поиск (с опциональным ИИ-уточнением), главная с блоками
  «Новое / Популярное / Продолжить просмотр».
- Плейлисты (включая авто-«Смотреть позже»).
- Комментарии с **ИИ-модерацией** (mock-провайдер работает из коробки).
- Жалобы (спам / оскорбления / нарушение авторских прав / другое).
- Админ-панель: дашборд, пользователи, видео, комментарии, жалобы, ИИ-логи, настройки.
- Дизайн-система Liquid Glass: `glass.css` + `app.css`, `prefers-reduced-motion`.

---

## Требования

- PHP 8.2+ с расширениями `pdo_mysql`, `fileinfo`, `json`, `mbstring`.
- MySQL 8+ (или MariaDB 10.6+).
- Для ИИ в реальном режиме — доступ к провайдеру (OpenRouter / Groq / OpenAI-совместимый)
  и API-ключ. **Mock-провайдер работает без ключа.**

## Установка

### 1. Клонируйте / распакуйте проект

```
glass-tube/
├── app/            # Core, Controllers, Models, Services, Middleware, Views
├── public/         # index.php + assets (точка входа)
├── storage/        # videos/, thumbnails/, cache/ (вне webroot)
├── database/       # DATABASE.sql, seed.sql, seeds/seed.php
├── .env / .env.example
└── README.md, PLAN.md
```

### 2. Настройте окружение

Скопируйте `.env.example` в `.env` (в репозитории уже есть готовый `.env` для разработки)
и отредактируйте параметры БД:

```
cp .env.example .env
```

Основные переменные: `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`, `STORAGE_PATH`,
`VIDEO_MAX_MB`, `ENABLE_AI`, `AI_PROVIDER`, `AI_API_KEY`.

### 3. Создайте базу данных и импортируйте схему

```sql
CREATE DATABASE glass_tube CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

```bash
mysql -u root -p glass_tube < DATABASE.sql
mysql -u root -p glass_tube < seed.sql
```

### 4. Наполните демо-данные

```bash
php database/seeds/seed.php
```

Создаётся админ `admin@glasstube.local / admin1234` и демо-пользователь
`demo@glasstube.local / demo1234`, каналы, несколько демо-видео (без реальных
файлов — плеер показывает аккуратную заглушку) и комментарии.

### 5. Запуск

```bash
php -S localhost:8000 -t public public/index.php
```

Откройте **http://localhost:8000**.

> На Apache всё работает через `public/.htaccess` (online-роутинг на `index.php`).
> Убедитесь, что `mod_rewrite` включён, а документ-рут — `public/`.

### 6. Права на запись

Каталог `storage/` должен быть доступен для записи веб-серверу:
```bash
chmod -R 755 storage
```

## ИИ-интеграция

Все ИИ-запросы идут **только через сервер** (`AiService`). Ключ хранится в `.env`
(`AI_API_KEY`) и никогда не попадает в браузер.

### Mock-провайдер (по умолчанию)
`AI_PROVIDER=mock` — работает без ключа, возвращает безопасные тестовые JSON-ответы
для генерации метаданных, модерации, суммаризации, тегов и поиска.

### OpenRouter / Groq / OpenAI-совместимый
```dotenv
AI_PROVIDER=openrouter
AI_BASE_URL=https://openrouter.ai/api/v1
AI_API_KEY=sk-or-...
AI_MODEL=openai/gpt-4o-mini
```
Для Groq: `AI_BASE_URL=https://api.groq.com/openai/v1`, `AI_MODEL=llama-3.1-8b-instant`.
Для своего API: `AI_PROVIDER=custom_openai_compatible`, `AI_BASE_URL=<ваш base>/v1`.

Ответы валидируются и извлекаются из JSON (включая случаи в markdown-фразах),
кэшируются в `ai_cache`, лимитируются через `RateLimiter` и логируются в `ai_requests`.
При отключении (`ENABLE_AI=false`) или ошибке провайдера ИИ возвращает мягкий fallback.

## Безопасность

- PDO prepared statements везде (нет конкатенации пользовательского ввода в SQL).
- Экранирование вывода через `e()` (XSS).
- CSRF-токен в сессии для форм и заголовок `X-CSRF-Token` для fetch.
- Загрузка: проверка размера, MIME (`finfo`), белый список расширений, случайные имена,
  запись в `storage/videos/{user_id}/` вне webroot. Транзакция откатывает запись при сбое.
- Стриминг проверяет права (public / unlisted / private / статус) и отдаёт только
  через `/video/{id}/stream` (путь к файлу не виден клиенту).
- Проверка владельца при редактировании/удалении; роль `admin` для админки.
- Задержка при неверном входе (защита от перебора).
- `.htaccess` блокирует `.env`, исходники и выполнение загруженных скриптов.

## Настройка FFmpeg (опционально)

Если `ffprobe` доступен, при загрузке определяется длительность видео. Без FFmpeg
проект работает (длительность будет неизвестна, конвертация не производится).
Укажите пути в `.env`: `FFMPEG_PATH`, `FFPROBE_PATH`.

## Известные ограничения MVP

- Нет HLS / многокачественной конвертации (FFmpeg опционален, только ffprobe для длительности).
- ИИ реально не «смотрит» видео без транскрипта (честно указано в ответах).
- Нет очередей задач: видео сразу `published`, если не включена `REQUIRE_VIDEO_APPROVAL`.
- Демо-видео поставляются без файлов (заглушка в плеере).
